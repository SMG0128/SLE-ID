# 管理端本地后端实现日志（2026-08-09）

## 本轮结果

已按《SLE-ID 管理端后端与硬件通信方案 V1》完成第一版可运行后端，源码位于管理端仓库 `server/`。本轮仅实现后端，没有修改 Vue 管理端前端源码。

## 已实现

- Node.js 20+、TypeScript、Express 模块化单体；默认只监听 `127.0.0.1:8080`。
- SQLite WAL 数据库，事件、报警、确认、许可证、卡片、邀请码、命令和审计记录持久化。
- REST 统一 `{code,message,data}` 响应，覆盖现有管理端主要数据域。
- `/ws/events` WebSocket 推送设备、事件、报警、确认和策略结果。
- Windows USB 串口枚举与显式 COM 口选择；固定 115200/8N1，不扫描误开其他设备。
- 选择串口时等待 Detector B 合法心跳，避免把 A 板或普通 CH340 误认为 B。
- Protocol V2 完整帧编解码、CRC16-CCITT、混合文本日志过滤、坏帧重同步。
- Host 每秒心跳；B 心跳超过 3.5 秒未到达时清除 `detectorBReady`。
- Host `sourceId` 首次运行随机生成并持久化，`bootId` 每次进程启动更新。
- 已保存 COM 口在服务启动时暂时缺失，会进入指数退避自动重连。
- 事件/报警/确认在 SQLite 事务提交后才回复 ACK；重复帧回复 DUPLICATE。
- 策略下发、命令结果、确认结果、超时重试和失败记录。
- 策略版本全局单调递增，适配 B 仅保存一份活动策略的现状。
- 命令历史使用数据库自增主键，兼容 B 重启后本地 requestId 从头计数。
- 不支持的能力显式降级：远程重启返回 501；卡片动作标记 `pending_sync`；高级策略返回 capability 状态。
- 新增数据库 V2 迁移，可自动修复早期命令表的 requestId 唯一约束。
- 新增设备登记/命名、能力清单、审计日志查询和 SQLite 在线备份接口。
- 串口状态新增最后错误、错误时间和重连次数，便于管理端展示真实故障原因。
- 增加每日 SQLite 一致性备份调度，保留最近 7 份；退出时等待正在执行的备份完成后再关闭数据库。
- 非法 JSON 请求现在返回统一 `400 / code=1001`，不再误报服务端内部错误。
- 修复命令重试边界：USB 瞬断导致写入失败时保留原 requestId/payload，并在剩余次数内等待重连后继续发送。
- 策略最终超时或串口失败时明确更新许可证 `syncStatus=failed`，记录审计并推送失败结果。
- 串口原生写错误会主动关闭故障句柄并进入自动重连，避免 COM 句柄看似打开但实际不可写。

## 本轮发现并修复的问题

1. 初始生产编译目录包含 `dist/src/index.js`，但启动脚本指向 `dist/index.js`。已调整 TypeScript `rootDir`，生产启动路径验证通过。
2. 原命令表以 `(requestId, commandType)` 唯一，B 重启后 requestId 重用会冲突。已改为命令行自增主键并按主键更新结果。
3. 原策略版本按许可证分别加一，切换许可证时可能向 B 重复发送同版本并被判旧。已改为数据库全局策略版本序列。
4. 只验证 COM 打开不能证明接的是 B 板。设置串口接口现在必须在 3.5 秒内收到 B 身份心跳才保存。
5. WebSocket 客户端关闭握手可能拖住服务退出。关服时主动终止本地 WS 客户端。
